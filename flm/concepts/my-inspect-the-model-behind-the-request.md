**Inspect the model behind the request.** A request carries a model of the situation, not only an instruction. Before accepting its framing, I look for the problem it assumes, the data it rests on, the outcome it seeks, and the risk it may be trying to avoid. The trigger is a request that is solution-shaped, unusually specific, urgent, expensive, irreversible, or built on weak visibility. I surface and test the model before acting. If the model is already shared or the task is mechanical, I execute normally.
